### GitHub runners (`/runners`)

Observes GitHub Actions self-hosted runners and can explicitly, plan-first manage small Hetzner Linux x64 pools for the active exact `github.com` repository.

- Discovered under **engineering** by `/toggle`; it is **not auto-enabled**. Build first in `engineering/extensions/github-runners`: `npm ci --ignore-scripts && npm run build`.
- `/runners status|refresh|ensure|reconcile|drain|destroy` supports `--policy`, `--capacity`, `--instance`, and management `--apply`; mutation requires interactive confirmation and policy opt-in. Single-instance apply operations require explicit `--policy` when multiple policies exist. `destroy --all [--policy NAME] [--apply]` previews all configured pools (or the selected one), confirms the complete set, and binds each policy fingerprint; retry after safe drain quiescence to finish deletion. It does not disable automation or target unrelated Hetzner servers.
- Settings use a native searchable list with inline cycles, selection restoration after edits, and explicit Save/Discard. Saving enabled local automation can immediately reconcile or create billable capacity; it does not redeploy a remote snapshot. Settings are local `.pi/github-runners.json`, or explicit shared-org mode via `~/.pi/agent/github-runners.json`; never place tokens in JSON or CI VMs.
- `/runners reaper install|status|uninstall` lists literal aliases from `~/.ssh/config` plus manual entry, then installs one trusted-Linux SSH/systemd controller using a pre-provisioned private `0600` environment file. The selected alias is passed unchanged to current SSH config/agent/default keys; `BatchMode=yes` means no password/passphrase prompt (use `ssh-add` for locked keys), and host-key verification remains enabled. Listing does not connect; preflight occurs only after install confirmation. SSH keys are separate from GitHub/Hetzner environment credentials. Same-host/same-scope reinstall is transactional; changing host or scope requires uninstall first. Status is systemd health only; use controller stderr/journalctl for logs. Uninstall does not delete billable VMs or that environment file.
- A size mapping with `quantity: 0` is disabled, may remain an incomplete draft, and does not delete existing managed VMs. Footer is `busy/online runners`; `?/? runners` means status is unknown. Live verification covers existing-runner drain/deletion, not provisioning or remote deployment. See `README.md` for limits, required GitHub/Hetzner permissions, configuration schema, and remote-controller caveats.
